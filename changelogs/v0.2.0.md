# montygo v0.2.0

Second-stage API feedback cleanup. Upstream remains Monty 0.0.23 plus
main@f8acf4fa, wire protocol 3. No worker or server protocol change is required.

## Breaking changes

- Session and Run interruption now accept InterruptOptions and return
  `(InterruptResult, error)`. Options contain Reason and optional per-call Grace.
  Results distinguish stop outcome, actual Go completion and terminal session error.
- Overlapping executions return ErrSessionBusy, including while a snapshot is
  paused. There is no implicit queue. Go reserves its execution before returning.
- Grace expiry kills and retires workers even when a Go callback ignores
  cancellation. SessionKilledError wraps the first reason and matches ErrSessionLost.
  RunDone stays false until the synchronous driver returns.
- Deliberate ErrSessionClosed no longer matches ErrSessionLost.
- Reflected Host.Stubs parameters are positional-only, matching runtime calls.
  HostFuncOptions optionally supplies validated, copied parameter labels.

## Reliability

- Run handles and snapshot tokens target a durable execution. Old handles and
  timers cannot stop, resume, or poison a later execution.
- One interrupt request owns the first reason and deadline. Later requests can
  only shorten it. Caller timeout does not cancel an accepted stop.
- WaitContext is wait-only. Close bounds waiting; CloseNow does not join callbacks.
- Lease ownership is independent of protocol I/O. Retirement retains capacity
  until observed worker exit. Observer closure waits for active use.
- Future subscriptions are keyed by call ID and cleared on every terminal path.
  Shared caller Futures are never settled by session cleanup. Snapshot steps do
  not cancel successful pending work; derived conversion waits are cancellable.
- Every suspension and resume checks cancellation, including mounts and lookups.
  Canonical error publication preserves active shutdown dumps and force causes.
- Shutdown and final checkout tracking share admission synchronization.

## Guidance and parity

The README documents v0.1.0 migration, explicit per-object Record conversion,
and honest version stamping for directory replacements. No automatic recursive
struct conversion or runtime git discovery is added. These lifecycle APIs are
Go additions; upstream protocol, exception and limit parity remains unchanged.
See `docs/parity/api.md` and `docs/parity/tests.md` for the detailed mapping.

## Tests and limitations

Regression tests cover immediate interruption (1000 iterations per backend),
deterministic lifecycle ordering, shared Futures, snapshot ownership, force
during callbacks and checkout lease races. Verification includes native, wasm,
WebSocket, race detection, server/image/network checks, and executable examples.

Go cannot terminate an arbitrary callback goroutine. Force bounds worker
ownership, not the remaining Go work. Async work is not joined; host code must
honour cancellation for its own resources. Host stubs still omit attributes.
NamedTuple conversion of nested lists/maps remains explicit application code.

## Build notes

Versions still come from git tags through scripts/version.sh. Use make to stamp
builds; no binding version is hard-coded. A local directory replacement without
a stamp honestly reports development metadata. Worker rebuilds are not needed
for this API-only revision.
