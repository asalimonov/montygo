# montygo v0.0.23 — 2026-09-15

The first release of montygo, a Go binding for [Monty](https://github.com/pydantic/monty) with the feature set of the official TypeScript package `@pydantic/monty`.

## Upstream baseline

- Monty `0.0.23` plus upstream `main@f8acf4fa`. That commit is 25 commits past the `v0.0.23` tag, and it moves the wire protocol to **version 3**.
- Protocol 3 adds three things: `Print` events carry ordered segments from both streams, `Feed` carries the working directory (`cwd`), and `FunctionCall` can allow eager awaits.
- Workers built from the `v0.0.23` tag speak protocol 2 and reject this parent. Use a worker built at `f8acf4fa` or newer, or the embedded wasm worker.
- Interpreter changes included through the baseline:
  - print debouncing, and `print(file=sys.stderr)`
  - `str.format` and the `format()` builtin, plus percent formatting for `str` and `bytes`
  - `itertools` adaptors and more `math` aggregation functions
  - `binascii` conversions
  - `date.today()` / `datetime.now()`
  - long ints in `pow()`, `round()` and `math`
  - runtime generic types such as `tuple[int, str]`
  - better case methods
  - `sys` constants

## What's added

- **Pure-Go protocol parent.** montygo has no cgo and no in-process interpreter. A hand-written protobuf codec charges a per-frame memory budget and validates values while decoding.
- **Three backends behind one API:**
  - native `monty subprocess` workers (unix);
  - an embedded wasm32-wasip1 worker run in-process by wazero, compressed into the module, compiled once and cached on disk;
  - WebSocket workers (`NewWebSocket`), with per-checkout connect headers, disconnect and shutdown errors.
  - `BackendAuto` uses a native binary when one resolves and the wasm worker otherwise.
- **Pools and sessions.**
  - Pool options: `MinProcesses`, `MaxProcesses`, `CheckoutTimeout`, `RequestTimeout`, `DurationLimitGrace`, `MaxCheckoutsPerWorker`.
  - Sessions keep REPL state across `FeedRun` calls and are safe to hand between goroutines.
- **External lookup.** Host functions can be plain Go functions (adapted by reflection, keyword arguments in `monty.Kwargs`), `monty.Function` or `monty.FunctionFunc`. Async calls return `*monty.Future` and support eager awaits. Non-function entries are values, and `monty.Raise` raises typed Python exceptions.
- **Class instances and host classes.**
  - `ClassInstance` and `ClassType` carry eager, lazy and method policies, `ConvertValue`, identity round-trips, construction with `Init` and `Constructor`, and class statics.
  - `*ClassProxy` stands in for sandbox-defined instances.
  - Go members are exposed under snake_case names or `monty` field tags.
- **Snapshots.**
  - `FeedStart` returns single-use cursors: `FunctionSnapshot`, `NameLookupSnapshot` and `FutureSnapshot`.
  - `ResumeAuto` answers one step the way `FeedRun` would.
  - `Dump`, `LoadSession` and `LoadSnapshot` save and restore sessions.
- **Print output.** Print targets, `ContextPrintTarget`, and the `CollectString` / `CollectStreams` collectors with a 10 MiB default cap. `PrintFlushInterval` controls batching.
- **Filesystem.**
  - `MountDir` supports `read-only`, `read-write` and `overlay` modes. It is a descriptor-bound port of `monty-fs` with path security, symlink policy, and memory and write budgets.
  - Mounts work on every backend, including wasm.
  - OS handlers can return `NotHandled`, and `MontyFileHandle` equivalents are provided.
- **In-memory OS helpers** (package `osaccess`): `OSAccess`, `MemoryFile`, `CallbackFile`, `StatResult` and the `Ops` interface, ported from the Python binding.
- **Resource limits.** Memory, duration, recursion depth, GC interval and the suspension budget. Duration limits have a host-side backstop, and allocator breaches are classified as `MemoryError` on both native and wasm.
- **Type checking.** All nine ty diagnostic formats, colour, stubs and `SkipTypeCheck`; also assert message annotations.
- **Errors:**
  - `RuntimeError` renders tracebacks identical to Monty's;
  - also `SyntaxError`, `TypingError`, `CrashedError`, `DisconnectError`, `ShutdownError`, `ProtocolError`, `ConversionError`;
  - all implement `monty.Error`.
- **Observability.**
  - `monty.Instrument` and `NewInstrumentation` install OpenTelemetry tracers, meters and loggers process-wide.
  - Telemetry mirrors the protocol inside the pool, as `monty-pool` does. Spans cover sessions, runs, host round trips with their answers, and housekeeping turns. Log records cover print output and errors, and 14 metrics cover the pool, runs, host calls, snapshots and frames.
  - Host callbacks receive the innermost Monty span in their context. WebSocket dials propagate `traceparent` and `tracestate`.
- **Examples.** Go ports of every upstream Python example are in the `examples` module: the class-boundary examples, expense analysis, the SQL playground and the web scraper.
- **Tooling.** A `Makefile` for native and wasm worker builds, a CI workflow for Linux and macOS, runnable README examples, and an exported-API golden test.

## Parity with `@pydantic/monty`

| Area | Status |
|---|---|
| Pool, sessions, inputs, external lookup, async, snapshots, dumps | parity |
| Class instances, host classes, proxies | parity; JS prototype hardening replaced by Go visibility rules |
| Print callbacks and collectors | parity |
| Mounts and OS callbacks | parity, plus mounts on the wasm backend |
| Resource limits and crash recovery | parity; wasm memory breaches classified like native |
| Type checking and assert annotations | parity |
| Errors and traceback rendering | parity |
| OpenTelemetry | parity in span names, attributes, log records and metrics; recording is synchronous, histograms use the SDK default aggregation, and logfire-specific attributes are not emitted |
| wasm / browser entry | covered by the embedded wazero worker; browser Worker plumbing is not applicable |
| WebSocket transport, OS helpers | beyond the TypeScript package (from the Python binding) |
| Windows | not supported by the native backend; the wasm backend works |

## Test parity

- **TypeScript suite:** 28 upstream spec files. Every test title is a Go subtest, run on both the native and wasm backends; see `docs/parity/tests.md` for adapted and skipped tests.
- **Python binding:** `test_websocket.py` and the three `test_os_access*.py` suites are ported.
- **Rust crates:** the `monty-fs` suite (242 tests) and the `monty-pool` WebSocket scenarios are ported to the internal packages.
- **Differential tests:** the wire codec is checked against the generated protobuf types.

## Known limitations

- The first wasm pool in a process compiles the worker, which takes a few seconds cold and about 130 ms from the on-disk cache.
- A worker that ran the type checker keeps its caches after `Reset`, and a later session on that worker with a very small `MaxMemory` counts them against the limit. Recycle workers with `MaxCheckoutsPerWorker` when mixing type checking with tight memory limits.
- Host objects are exposed by reflection over exported members; computed attributes need `AttrProvider`.
- The TypeScript package's trailing options-bag convention for keyword arguments becomes a `monty.Kwargs` parameter.
- Upstream `examples/sql_playground/sandbox_code.py` imports its stubs as `type_stubs`, but session type checking names them `repl_type_stubs`. The upstream example fails its type check at this baseline. The Go port configures type checking and skips it for that feed unless `-type-check` is passed.

## Build notes

- Rebuilding the embedded worker needs Rust 1.95+ with the `wasm32-wasip1` target (`make build-wasm`).
- On macOS with a beta SDK, the Makefile selects the 26.5 SDK for cargo through `SDKROOT`.
