# montygo v0.3.0

API redesign: a `Runtime` holds the sandbox configuration, a `Pool` manages
workers from a `WorkerSource`, the library owns how a run ends, and nothing is
global. Upstream remains Monty 0.0.23 plus main@f8acf4fa, wire protocol 3. No
worker, wire or server protocol change is required.

## Breaking changes

- **Runtime and pool.** `montygo.New(ctx, Options{Backend, ...})` is replaced by
  `montygo.NewPool(ctx, PoolOptions{Workers: Native(...) | Wasm(...) | Remote(...) | Auto(), ...})`;
  `MinProcesses`/`MaxProcesses` are `MinWorkers`/`MaxWorkers`, `BinaryPath`,
  `WasmCacheDir` and `DisableWasmCache` moved into `NativeOptions` and
  `WasmOptions`, and `Pool.Backend()` is `Pool.Workers()`. The sandbox
  configuration left `CheckoutOptions`: `NewRuntime(RuntimeOptions{Host, OS,
  Mounts, Print, Limits, TypeCheck, TypeCheckStubs, TypeCheckFormat,
  TypeCheckColor, AssertMessageAnnotations, PrintFlushInterval, MaxHostObjects,
  MaxPendingFutures})` validates it once, and `Pool.Checkout(ctx, rt,
  CheckoutOptions{ScriptName, Limits, Stop})`, `Pool.Run(ctx, rt, code, opts)`
  and `Pool.Slot(rt, opts)` take the runtime. `FeedOptions.OS` and
  `LoadSnapshotOptions.OS` are gone; the runtime's handler serves every feed.
- **Packages.** The root package no longer aliases other packages. Value types
  are in `sandbox` (`sandbox.Dict`, `sandbox.Path`, `sandbox.Lines`, ...), host
  objects in `sandbox/host` (`host.NewHost`, `host.Async`, `host.Kwargs`,
  `host.Expose`, ...), every error in `monterr` (`monterr.RuntimeError`,
  `monterr.ErrSessionLost`, `monterr.OptionError`, ...), and the OS helpers in
  `sandbox/osaccess`.
- **Remote workers.** `NewWebSocket` and `WebSocketOptions` are replaced by
  `Remote(sup, RemoteOptions{DialTimeout, TLSConfig, DialContext, Recovery,
  RotateSessions, RotationMargin})`, where `sup` is a `ServerSupervisor`;
  `StaticServer(url, tlsConfig, headers)` is the supervisor of a fixed URL.
  `CheckWebSocketHealth` and `FetchServerInfo` take `(ctx, sup, RemoteOptions)`
  as `CheckServerHealth` and `FetchServerInfo`. `RequestTimeout` is the per-turn
  deadline only; the dial budget is `RemoteOptions.DialTimeout`.
- **Telemetry.** `Instrument`, `Flush`, `TelemetryComponents`,
  `Instrumentation.Enable`, `Disable`, `ForceFlush` and `ErrTelemetryPresent` are
  removed. A pool records into `PoolOptions.Telemetry *telemetry.Components`;
  `telemetry.Instrumentation.Components()` builds them from providers. Nothing
  is installed process-wide.
- **Stop policy.** `DefaultStopPolicy` is removed: the built-in policy
  (`Timeout` 3 s, `Join` 3 s) is a constant overridden by `PoolOptions.Stop`.
- `Run.Interrupt`, `Session.Interrupt`, `InterruptOptions`, `InterruptResult`,
  `InterruptOutcome` and its eight constants are removed. `Run.Stop(ctx, policy...)`
  and `Session.Stop(ctx, policy...)` return `(Stopped, error)` after the run
  has ended: `Stopped{How, Err, SessionErr}`, `Stopped.SessionKept()`, and a
  `StopKind` of `StopPending`, `StopNotRunning`, `StopAborted`, `StopKilled` or
  `StopFinished`.
- `CheckoutOptions.InterruptGrace` is removed. `StopPolicy{Drain, Timeout, Join,
  Reason, Catchable}` replaces it at four levels: the built-in policy,
  `PoolOptions.Stop`, `CheckoutOptions.Stop`, and the call. Zero fields
  inherit. `montygo.KillNow` kills at once.
- `Session.CloseNow` is removed: use `Session.Close(ctx, montygo.KillNow)`.
  `Session.Close(ctx, policy...)` stops a running feed with the policy first, so
  `defer session.Close(ctx)` is always safe. When the caller's context ends
  first it returns `ctx.Err()` and the close continues in the background.
- `Pool.Shutdown(ctx, policy...)` ends admission, closes every open session with
  the policy concurrently and waits for every worker within `ctx`. Running feeds
  are stopped at once unless `Drain` is set. The 5 s force grace and
  `internal/pool` `Config.OnShutdown` are gone.
- A cancelled feed context (`Go`, `FeedRun`, `FeedStart` steps) ends the run
  through the session's stop policy instead of killing the worker while Python
  executes: `FeedRun` returns `KeyboardInterrupt` with the session kept where
  Python yields, or a `*SessionKilledError` after `Timeout` where it does not.
- `Host.Stubs` writes the positional-only `/` marker only after a fixed
  parameter, so a parameterless method renders as `def reset(self) -> None: ...`.

### Migration

| v0.2.0 | v0.3.0 |
|---|---|
| `run.Interrupt(ctx, InterruptOptions{Reason: r, Grace: DurationPtr(d)})` | `run.Stop(ctx, StopPolicy{Reason: r, Timeout: d})` |
| `result.Outcome == InterruptAborted` / `InterruptKilled` / `InterruptFinished` / `InterruptNotRunning` / `InterruptPending` | `stopped.How == StopAborted` / `StopKilled` / `StopFinished` / `StopNotRunning` / `StopPending` |
| `InterruptBeforeStart`, `InterruptAlreadyFinished`, `InterruptUnknown` | `StopAborted`, `StopFinished`; no zero-value outcome |
| `result.RunDone` then `run.WaitContext(ctx)` | `Stop` returns after the run ended; `stopped.Err` is `run.Wait()`'s error |
| `CheckoutOptions{InterruptGrace: d}` | `CheckoutOptions{Stop: StopPolicy{Timeout: d}}` |
| `session.CloseNow()` | `session.Close(ctx, montygo.KillNow)` |
| `pool.Shutdown(ctx)` and its force grace | `pool.Shutdown(ctx)`; `pool.Shutdown(ctx, StopPolicy{Drain: d})` to let feeds end first |
| `montygo.New(ctx, Options{Backend: BackendWasm})` | `montygo.NewPool(ctx, PoolOptions{Workers: montygo.Wasm(WasmOptions{})})` |
| `pool.Checkout(ctx, CheckoutOptions{Host: h, TypeCheck: true})` | `rt, _ := montygo.NewRuntime(RuntimeOptions{Host: h, TypeCheck: true}); pool.Checkout(ctx, rt, CheckoutOptions{})` |
| `montygo.NewWebSocket(ctx, WebSocketOptions{URL: u})` | `montygo.NewPool(ctx, PoolOptions{Workers: montygo.Remote(montygo.StaticServer(u, nil, nil), RemoteOptions{})})` |
| `montygo.NewDocker(ctx, DockerOptions{...})` | `sup, _ := docker.New(ctx, docker.Options{...}); montygo.NewPool(ctx, PoolOptions{Workers: montygo.Remote(sup, RemoteOptions{RotateSessions: true})})`; close `sup` after the pool |
| `montygo.Instrument(TelemetryComponents{...})` | `PoolOptions{Telemetry: &telemetry.Components{...}}` |
| `montygo.Dict`, `montygo.NewHost`, `montygo.RuntimeError` | `sandbox.Dict`, `host.NewHost`, `monterr.RuntimeError` |
| `Options.BinaryPath`, `WasmCacheDir`, `DisableWasmCache`; `Pool.Backend()` | `NativeOptions.BinaryPath`, `WasmOptions.CacheDir`, `WasmOptions.DisableCache`; `Pool.Workers()` |
| `FeedOptions.OS`, `LoadSnapshotOptions.OS` | `RuntimeOptions.OS` |
| `CheckWebSocketHealth(ctx, opts)`, `FetchServerInfo(ctx, opts)` | `CheckServerHealth(ctx, sup, RemoteOptions)`, `FetchServerInfo(ctx, sup, RemoteOptions)` |
| `DefaultStopPolicy` | the built-in policy, overridden by `PoolOptions.Stop` |

`DurationPtr` stays for `PrintFlushInterval`.

## New

- **Stop policy.** One timeline for `Stop`, `Close`, `Shutdown` and feed-context
  cancellation: `Drain` lets the run end on its own; the request delivers
  `Reason` (default `KeyboardInterrupt`) at the next host call, await or
  suspension and cancels the callback context; `Timeout` kills the worker; `Join`
  bounds the wait for a Go callback that ignores its context, after which `Stop`
  returns `ErrCallbackDetached`. The caller's context bounds only its wait; an
  accepted stop always completes. Repeated stops join the first and can only
  shorten its deadlines.
- **Catchable stops.** `StopPolicy.Catchable` raises the reason inside the
  sandbox at the next host call or await, so `except KeyboardInterrupt` can run
  cleanup that makes further host calls under a live callback context. A caught
  stop that completes reports `StopFinished`; an uncaught one `StopAborted`. A
  catchable stop of a paused `FeedStart` snapshot falls back to `AbortFeed`.
- **Runtime.** `montygo.NewRuntime(RuntimeOptions{...})` validates a sandbox
  configuration once and returns an immutable `*Runtime` that any number of
  sessions of any number of pools share: host registry, OS handler, mounts,
  default print target, limits, type checking and host-side bounds.
  `Runtime.Options()` returns a copy.
- **Worker sources.** `PoolOptions.Workers` is a `WorkerSource` from `Native`,
  `Wasm`, `Remote` or `Auto`; `Pool.Workers()` reports the `WorkerKind`.
- **One-shot runs.** `Pool.Run(ctx, rt, code, *RunOptions{CheckoutOptions,
  FeedOptions})` checks out, feeds once and closes.
- **Slots.** `Pool.Slot(rt, opts)` returns a `*Slot` that owns at most one session,
  checks out lazily and again after a loss (sandbox state is not restored), and
  offers `Session`, `State`, `Go`, `FeedRun`, `FeedStart`, `Stop` and `Close`.
  `Go` returns `ErrSessionBusy` on overlap and `ErrSessionClosed` after `Close`.
- **Session state.** `Session.State()` reports `SessionIdle`, `SessionRunning`,
  `SessionPaused` or `SessionClosed`.
- **Method parameter names.** `ClassInstanceOptions.ParameterNames` and
  `ClassTypeOptions.ParameterNames` label method and static parameters in
  `Host.Stubs` by sandbox name, validated at registration; instance names
  override class names.
- **Examples.** `examples/oneshot` (`Pool.Run`) and `examples/service` (a
  `Slot` running an endless loop with a `Host`, stopped on SIGINT by `Run.Stop`,
  then `Slot.Close` and `Pool.Shutdown`). `examples/repl` stops a snippet with
  `Run.Stop` on Ctrl-C and replaces the session only after a kill.

### Supervisors and session rotation

- **`supervisor/docker`.** `docker.New(ctx, docker.Options{...})` starts a
  `monty-server` container through the local `docker` CLI and serves its
  endpoint to pools built with `montygo.Remote`. The image tag comes from
  `BindingVersion()`: the exact version, then the release it was built from, so
  a program built against `montygo v0.3.0` runs
  `ghcr.io/asalimonov/monty-server:0.3.0`. Each candidate is used from the local
  daemon when present, else pulled. `Options.Image` / `Version` and
  `MONTYGO_DOCKER_IMAGE` / `MONTYGO_DOCKER_VERSION` override it, an option winning
  over a variable. A version that yields no tag, such as `(devel)`, is an
  `OptionError` naming the overrides. `Options.MaxSessions` sizes the server.
  The application closes the supervisor after the pools; `Auto()` never
  contacts Docker.
- **Supervisors.** `ServerSupervisor` resolves a `ServerEndpoint` before every
  dial and MAY restart a failed server; it is declared in the root package, so
  an application implements it for servers elsewhere. `StaticServer` covers a
  fixed URL.
- **Recovery.** `RemoteOptions.Recovery`, a `RecoveryPolicy{Attempts,
  AttemptTimeout, RestartServer}`, retries a supervised dial, 3 attempts of 5 s
  by default, and with `RestartServer` performs one single-flight server restart
  before retrying. Exhaustion is a `*monterr.SpawnError`.
- **Session rotation.** A `monty-server` closes a session after its session
  timeout, 3600 s by default, without a dump. A pool with
  `RemoteOptions.RotateSessions` dumps the session, reconnects and restores it
  before that deadline, keeping the same `*Session`, its runtime, its
  suspension budget and its working directory. The rotation happens between
  operations, so no execution is cut short. A failure ends the session with
  `*monterr.RotationError`, whose `Dump` restores the state on a new session.
- **Container settings.** The container runs `--read-only`, `--cap-drop ALL` and
  `--security-opt no-new-privileges` on an ephemeral loopback port, with a random
  dump key passed through the environment. The server's idle timeout and its
  memory and duration ceilings are disabled, so the runtime's limits govern as
  on native; the session and turn timeouts stay at their defaults, because rotation
  relies on the turn timeout bounding every execution. `Options.Env` and
  `RunArgs` override anything.
- **`supervisor/native`.** `native.New(ctx, native.Options{...})` runs
  `monty-server` as a child process on an ephemeral loopback port, for hosts
  with the server binary but no container runtime. It resolves the binary from
  `Options.Binary`, `MONTYGO_SERVER_BIN`, then `PATH`, and applies the same
  limit policy as the Docker supervisor.
- **Tests.** A `docker` backend joins `MONTY_TEST_BACKENDS`, and `make test-docker`
  runs the whole root suite through `docker.New`, one container per pool.
- **`monty-server` OTLP exports retry.** A failed span or log export is retried
  for about 12 s and logged (`otlp_export_failed`, `otlp_export_dropped`); the
  first delivery per signal logs `otlp_export_established`.

### Package layout

- The root package holds the engine and the API; `sandbox`, `sandbox/host`,
  `sandbox/osaccess`, `monterr`, `telemetry`, `supervisor/docker` and
  `supervisor/native` hold the rest. The root aliases nothing, and the library
  keeps no process-wide state.
- **Breaking:** `github.com/asalimonov/montygo/osaccess` is now
  `github.com/asalimonov/montygo/sandbox/osaccess`. The package contents are
  unchanged; only the import path moves.
- The upstream pins stay in `montygo.go`; `internal/buildinfo` carries only the
  binding version. The `-ldflags "-X github.com/asalimonov/montygo.buildVersion=…"`
  stamp is unchanged.

## Guidance and parity

Rely on the defaults: `run.Stop(ctx)` delivers `KeyboardInterrupt`, kills
after 3 s and joins for 3 s. Set `PoolOptions.Stop` or `CheckoutOptions.Stop` to
change a budget for a pool or a session, and pass a policy to one call to
change it once. `Catchable` cannot be switched off per call once a checkout
set it; use `KillNow` or a short `Timeout`. A run that the worker or the server
ended first reports `StopFinished` with the loss error, so check `SessionKept`
rather than the kind before reusing a session. These lifecycle APIs are Go
additions; upstream protocol, exception and limit parity is unchanged. See
`docs/parity/api.md` and `docs/parity/tests.md`.

## Tests and limitations

`stop_test.go` covers policy levels, `Drain`, `KillNow`, catchable delivery,
repeated stops, `Close` with a policy, `Session.State`, `Pool.Run`, `Shutdown`
with `Drain` and `Slot`, on every backend. The lifecycle, execution and
cancellation suites are migrated to `Stop`. `tests/network` adds a server
close during a stop, reported as `StopFinished` with a `DisconnectError`.

Go cannot terminate an arbitrary callback goroutine: a kill bounds worker
ownership, `Join` bounds the wait, and `ErrCallbackDetached` names the leak.
A `Slot` does not restore sandbox state after a loss. A pool's stop policy and
telemetry components are fixed at `NewPool`. Server-side timeouts are not
clamped to the client policy. A feed mount at the same virtual path as a
runtime mount is layered after it, as upstream layers overlapping mounts.
