# montygo v0.1.0 — 2026-09-15

The first tagged release of montygo. It keeps the upstream baseline of v0.0.23 and works through the review feedback in `docs/reports/feedback.md`: bounded worker queues, an explicit session lifecycle with interruption and abort, pool accounting and shutdown, a host registry, per-pool telemetry, server info, codec evidence and release engineering. Versions now come from git tags.

## Upstream baseline

- Unchanged: Monty `0.0.23` plus upstream `main@f8acf4fa`, wire protocol **3**. Workers built from the `v0.0.23` tag speak protocol 2 and are rejected; build the native worker from the pinned revision or use the embedded wasm worker.
- `scripts/check-pins.sh` (`make check-pins`) verifies that every copy of the upstream revision and Monty version matches `proto/PROTO_REV` and `montygo.go`. CI runs it first.

## What's changed (breaking)

- The root package is `montygo`, matching the module path: `import "github.com/asalimonov/montygo"` with no alias, and `montygo.New`, `montygo.Options` and so on. `monty.go` is now `montygo.go`.
- `montygo.All` is a function: `montygo.All()` returns the exposure policy that was the `All` variable. `montygo.Expose[T]()` builds a policy from the methods of an interface type, under their sandbox names; it panics for a non-interface type.
- `PythonExceptionNames` is replaced by `KnownExceptionNames()`, which returns a sorted copy.
- `Version` is deprecated. `MontyVersion` names the upstream release this binding tracks and `BindingVersion()` reports this module's own version: the value stamped with `-ldflags "-X github.com/asalimonov/montygo.buildVersion=..."`, else the module version from build info, else `0.0.0-unknown`. The WebSocket user agent and the telemetry scope version use `BindingVersion()`.
- Cancelling the feed context while the worker waits on a host call now sends `AbortFeed(KeyboardInterrupt)` to the worker, so the feed returns a `*RuntimeError` with `TypeName` `KeyboardInterrupt` and the session survives; before, the worker was killed and the session poisoned. The sandbox cannot catch the interrupt. Cancelling while Python executes still kills the worker. A `ResolveFutures` wait is cancelled the same way.
- Host callbacks receive a context that follows the feed context for cancellation and reads values from the turn context, so `Interrupt`, `CloseNow` and a cancelled caller context end a running host call's context while caller values and the Monty span still reach it.
- Telemetry is resolved per pool when the pool is created: `Options.Telemetry` and `WebSocketOptions.Telemetry` select components; nil uses the process-wide installation from `montygo.Instrument` at that moment. Installing components after a pool exists no longer affects it.
- `ErrSessionClosed` is a typed value with the same text; it also matches `ErrSessionLost`.

## What's added

- **Versioning.** `scripts/version.sh` derives the version from git: the `vX.Y.Z` tag at `HEAD`, else the highest reachable tag plus the short hash, else `0.0.0-<hash>`, with `-dirty` on a modified tree. `make version` prints it; every Go target and the Docker images are stamped with it, and the server reports it on `/`, `/info` and `monty_server_build_info`.
- **Bounded frame queue.** `Options.MaxPendingBytes` (default 64 MiB, `UnlimitedPendingBytes` disables) bounds worker output buffered by the parent per native and wasm worker; the reader blocks and the worker stalls on its write instead of growing host memory. WebSocket workers buffer one frame and are not affected.
- **Session lifecycle.** `Session.Interrupt(ctx, reason)` stops the running feed: during a host call it aborts the feed with `KeyboardInterrupt` (or the exception `reason` maps to) and keeps the session; while Python executes it waits `CheckoutOptions.InterruptGrace` (default 100 ms) and kills the worker; on a suspended `FeedStart` snapshot it aborts at once, and the next `Resume*` returns the error. `Session.CloseNow` ends a running feed with `ErrSessionClosed` and kills the worker. `Session.Done` and `Session.Err` report a closed or lost session, including a worker that dies while idle. `Session.Go` runs a feed on its own goroutine and returns a `*Run` with `Wait`, `Done` and `Interrupt`. `Session.Stats` reports host objects, their peak and pending futures.
- **Pool accounting and shutdown.** `Pool.Stats` reports `Starting`, `Active`, `Idle` and `Retiring` workers; all four count toward `MaxProcesses`. Retirement runs through at most 8 reaper goroutines. A worker whose session is lost is killed at once when local, or gets its close frame from the reaper when remote. `Pool.Shutdown(ctx)` closes the pool and waits for every session and worker; when `ctx` ends first, open sessions are closed with `CloseNow`, the wait continues for 5 s and `ctx.Err()` is returned when workers remain. `Pool.Close` keeps its meaning. `Checkout` after `Shutdown` returns `ErrPoolClosed`.
- **Lost sessions.** `*DisconnectError` carries the WebSocket close frame's `Code` and `Reason`, with the text `closed by server (<code>): <reason>`; `Code` is 0 when the connection dropped without one. `ErrSessionLost` is matched by `errors.Is` on `*CrashedError`, `*DisconnectError`, `*ShutdownError`, `*ProtocolError` and `ErrSessionClosed`, from `Session.Err` and from every later call.
- **Limits.** `montygo.Unlimited` and `UnlimitedDuration` are explicit sentinels; zero keeps the default, and `MaxRecursionDepth` cannot be unlimited. `MaxSuspensions` is documented as per session, as it is counted; `LoadSession` and `LoadSnapshot` reset the count. `CheckoutOptions.MaxHostObjects` (default 10 000; instances and their class types count) bounds the objects a session keeps for identity and `MaxPendingFutures` (default 1000) bounds unresolved futures per feed. Exceeding either raises `RuntimeError: <resource> limit N exceeded` in the sandbox and reaches the host as `*ResourceError`; the session stays usable. `montygo.AsyncContext(ctx, fn)` runs asynchronous host work under the callback context, so it observes an interrupt or a cancelled feed.
- **Host registry.** `montygo.NewHost` builds a `Host`; `Host.Func` and `Host.Object` validate names (Python identifiers, unique) and signatures at registration. `CheckoutOptions.Host` exposes the registry to every feed; `FeedOptions.ExternalLookup` entries override its names. `Host.Names` lists them, `Host.Stubs` renders Python stubs for `TypeCheckStubs` (functions and allowed methods; attributes are not declared). `Host.Restorable` reports the first object without a pinned `ClassInstanceOptions.ID` as `ErrHostObjectNotRestorable`, and `LoadSession` on a session with a `Host` returns it before loading; pinned ids let a dump find its objects again after `LoadSession` on another checkout with the same `Host`.
- **Values.** `montygo.AsNamedTuple(struct)` converts a struct's exported fields, in declaration order and under their `monty` tag or snake_case names, into a `NamedTuple`; `montygo.NewNamedTuple(typeName, pairs...)` builds one from unique, non-empty field names.
- **Print.** `montygo.Lines(fn)` delivers complete lines per stream without their newline. A `FlushingPrintTarget` has `Flush` called when a feed or turn ends, so a trailing partial line is delivered.
- **Server info.** `GET /info` returns the server version, upstream revision, protocol version and effective limits (seconds and bytes; 0 means disabled). `montygo.FetchServerInfo(ctx, WebSocketOptions)` fetches it as `*ServerInfo` with `ServerLimits`, through the same transport, headers and timeout as a checkout; `ErrNoServerInfo` marks a server without the endpoint.
- **Telemetry.** `Options.Telemetry` and `WebSocketOptions.Telemetry` give a pool its own components; a value with no components records nothing. Two metrics are added: `monty.pool.workers.retiring` and `monty.pool.pending_frame_bytes`, both up/down counters.
- **Codec evidence.** Benchmarks compare the hand-written codec with the generated `montypb` code (`make bench`); two fuzz targets check the event decoder against protobuf and round-trip requests through the encoder (`make fuzz`, 30 s per target in CI); a field-coverage test parses `monty.proto` and fails when the codec's field table and the schema diverge.
- **Release engineering.** CI runs `make check-pins`, the race detector, `govulncheck`, `cargo audit`, and the fuzz targets on Linux; tags `v*` build and push the multi-arch image to `ghcr.io` with SBOM and provenance from a clean tree. The image bundles the Rust licences at `/usr/share/licenses/monty-server/THIRD_PARTY_RUST.html`.
- **`montypb`.** The generated protobuf package stays public for consumers speaking the raw protocol. It is documented as unstable: it carries no promise beyond `montygo.ProtocolVersion` and is regenerated on every protocol change.

## Parity with `@pydantic/monty`

| Area | Status |
|---|---|
| Pool, sessions, inputs, external lookup, async, snapshots, dumps | parity, plus `Shutdown`, `Stats`, `Interrupt`, `CloseNow`, `Go`/`Run`, `Done`/`Err` and `AsyncContext` |
| Class instances, host classes, proxies | parity; `Host` registry, `Expose[T]`, `AsNamedTuple` and `NewNamedTuple` are Go additions |
| Print callbacks and collectors | parity, plus `Lines` and turn-end flushing |
| Mounts and OS callbacks | parity, plus mounts on the wasm backend |
| Resource limits and crash recovery | parity; explicit `Unlimited` sentinels, `MaxHostObjects`, `MaxPendingFutures` and `MaxPendingBytes` are Go additions |
| Type checking and assert annotations | parity |
| Errors and traceback rendering | parity; `ResourceError`, `ErrSessionLost`, `Is` methods and `DisconnectError.Code`/`Reason` are Go additions |
| OpenTelemetry | parity in names, attributes, log records and metrics, plus two pool metrics; components are resolved per pool |
| Cancellation | deviation: cancelling during a host call aborts the feed with `KeyboardInterrupt` instead of killing the worker; see `docs/parity/tests.md` and `docs/parity/api.md` |
| WebSocket transport, OS helpers, server info | beyond the TypeScript package |
| Windows | not supported by the native backend; the wasm backend works |

## Known limitations

- The first wasm pool in a process compiles the worker, which takes a few seconds cold and about 130 ms from the on-disk cache.
- A host function that ignores its context keeps an interrupted feed blocked until it returns; `Interrupt` kills the worker after the grace period only when no host call is running.
- `Host.Stubs` declares functions and allowed methods only; attributes of host objects are not declared, so a type-checked feed cannot read them directly.
- `Pool.Shutdown` settles pending futures with `ErrSessionLost`; goroutines started by `Async` keep running.
- A worker that ran the type checker keeps its caches after `Reset`; recycle workers with `MaxCheckoutsPerWorker` when mixing type checking with tight memory limits.
- The hand-written codec is stricter than protobuf about wire types and value semantics, and laxer in three documented ways it does not inspect: field numbers above the protobuf maximum, UTF-8 validity of string fields, and the payload bytes of `Unit`-typed arms. The fuzz target records these.
- Upstream `examples/sql_playground/sandbox_code.py` still fails its type check at this baseline; the Go port skips that check unless `-type-check` is passed.

## Build notes

- Build with `make`: targets pass `-ldflags` with the version from `scripts/version.sh`. A plain `go build` yields `BindingVersion()` from build info, or `0.0.0-unknown` in a replaced checkout.
- Rebuilding the embedded worker needs Rust 1.95+ with the `wasm32-wasip1` target (`make build-wasm`). On macOS with a beta SDK the Makefile selects the 26.5 SDK through `SDKROOT`.
- `make docker-push REGISTRY=...` requires a clean tree; a `-dirty` version is rejected by the release job.
- `make fuzz FUZZTIME=30s` and `make bench` run the codec evidence locally.
