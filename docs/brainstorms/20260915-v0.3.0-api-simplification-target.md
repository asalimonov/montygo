# Target: montygo v0.3.0 — stop policy, one-shot runs, slots, method stubs

Date: 2026-09-15. Base revision: `8b86307` (v0.2.0). Design record:
`20260915-v0.3.0-api-simplification.md`.

## 1. Initial request

Implement the "Recommendations for 0.3.0" of
`../montygo-test/docs/reports/20260915-montygo-v0.2.0-api-assessment.md`
(§4 Concerns, §6 Recommendations) with these constraints from the user:

- The stop helper concept is right; `Run.Stop(ctx, StopOptions{...}) (StopSummary, error)` as sketched is not. The default logic MUST live in the library, not in the application.
- No stability boundary yet; APIs may break in 0.x.
- Add a short copyable example that relies on the library defaults.
- v0.3.0 focuses on simplification: default behaviour inside the library, an API that is short for the simple scenarios and still readable and maintainable.
- The library MUST own a default timeout policy ("for instance 3 seconds; if it has not exited, kill it"), configurable globally and overridable per call.
- Pull in: draining shutdown, a catchable Python stop, an auto-reacquiring session holder.

## 2. High-level view

```
 application                          montygo (package montygo)
 ┌──────────────────────────┐         ┌──────────────────────────────────────────────┐
 │ pool.Run(ctx, code, o)   │──one-shot──▶ Checkout → FeedRun → Close(policy)         │
 │                          │         │                                              │
 │ slot := pool.Slot(o)     │         │ Slot ── owns ≤1 Session, re-checks out after │
 │ run, _ := slot.Go(...)   │──────▶  │        loss ── Session.Go ──▶ Run             │
 │ stopped, _ := run.Stop() │──────▶  │ Run.Stop ─┐                                  │
 │ session.Close(ctx)       │──────▶  │ Close ────┼─▶ stopRequest (policy) ──▶ lifecycle
 │ pool.Shutdown(ctx)       │──────▶  │ Shutdown ─┘   drain → request → kill → join  │
 └──────────────────────────┘         └──────────────────────────────────────────────┘
 policy resolution:  DefaultStopPolicy ⊂ Options.Stop ⊂ CheckoutOptions.Stop ⊂ call
                                       (resolved at checkout)      (per call)
```

Stop timeline (one policy for `Stop`, `Close`, `Shutdown` and feed-context cancellation):

```
t0           Stop called
t0+Drain     request: Reason delivered at the next host call / await / suspension
             Catchable=false → AbortFeed (uncatchable, session kept)
             Catchable=true  → resume with the exception (catchable), callbacks rotated
t0+Drain+Timeout   run not ended → worker killed (SessionKilledError, session lost)
             +Join             → Go callback still running → ErrCallbackDetached
```

## 3. Decisions

| # | Topic | Options considered | Chosen |
|---|---|---|---|
| D1 | Simple stop | `Run.Stop` complete default; `Interrupt` made complete; `Session.Stop` only; `Run.Cancel` | `Run.Stop(ctx, policy ...StopPolicy) (Stopped, error)` + `Session.Stop` |
| D2 | Timeouts | caller ctx as the only bound; library default | library-owned `StopPolicy{Drain, Timeout, Join, Reason, Catchable}`; default 0 / 3 s / 3 s / KeyboardInterrupt / false |
| D3 | Configuration | 3 levels; 4 levels; functional options | 4 levels: `DefaultStopPolicy` → `Options.Stop`/`WebSocketOptions.Stop` → `CheckoutOptions.Stop` → call |

| D6 | Feed ctx | keep phase behaviours; policy; policy for `Go` only | session policy for `Go` and `FeedRun` |
| D7 | Shutdown | drain until ctx then stop; stop at once | stop at once; `Drain` field opt-in |

## 4. Storage

No database, no cache, no persistent state. Nothing in `internal/pool`,
`internal/wire`, `internal/worker`, the server or the protocol changes.
Upstream parity of exceptions, limits and telemetry names is unaffected.

## 5. Public API

### 5.1 `stop.go` — CREATED (replaces `interrupt.go`)

```go
// StopPolicy says how an execution is ended. Zero fields inherit from the
// level above (call → checkout → pool → DefaultStopPolicy).
type StopPolicy struct {
    // Drain waits this long for the run to end on its own before the request.
    Drain time.Duration
    // Timeout: from the request until the worker is killed when the run has
    // not ended. Negative kills at once (see KillNow).
    Timeout time.Duration
    // Join: after a kill, how long Stop waits for a detached Go callback.
    Join time.Duration
    // Reason is raised in the sandbox; nil means KeyboardInterrupt.
    Reason error
    // Catchable delivers Reason as an ordinary exception at the next host
    // call or await instead of AbortFeed, so Python can catch it.
    Catchable bool
}

// DefaultStopPolicy is the process-wide default; set it before creating pools.
var DefaultStopPolicy = StopPolicy{Timeout: 3 * time.Second, Join: 3 * time.Second}

// KillNow ends an execution without a request phase.
var KillNow = StopPolicy{Timeout: -1}

// StopKind classifies how a stop ended.
type StopKind uint8

const (
    StopPending    StopKind = iota // the stop is still in progress (only with a ctx error)
    StopNotRunning                 // nothing was running
    StopAborted                    // the reason ended the run; the session is kept
    StopKilled                     // the worker was killed at Timeout
    StopFinished                   // the run ended on its own; Err is its result
)

func (k StopKind) String() string // "pending", "not running", "aborted", "killed", "finished"

// Stopped is the result of Stop.
type Stopped struct {
    How StopKind
    // Err is what Run.Wait returns for the run.
    Err error
    // SessionErr is the session's terminal error, nil while it is usable.
    SessionErr error
}

func (s Stopped) SessionKept() bool // SessionErr == nil

// ErrCallbackDetached: the worker was killed but a Go callback did not return within Join.
var ErrCallbackDetached = errors.New("montygo: host callback still running after kill")

func (r *Run) Stop(ctx context.Context, policy ...StopPolicy) (Stopped, error)
func (s *Session) Stop(ctx context.Context, policy ...StopPolicy) (Stopped, error)
```

`Stop` errors: `*OptionError` for an invalid policy (negative `Drain` or
`Join`, more than one policy argument), `ctx.Err()` when the caller stopped
waiting (the stop continues on its own; `How == StopPending`),
`ErrCallbackDetached` (`How == StopKilled`). A stop never returns
`ErrSnapshotStale`: a `Run` whose execution is no longer current reports
`StopFinished`.

### 5.6 `slot.go` — CREATED

```go
// Slot owns at most one session checked out with fixed options. It checks
// out lazily and again after the session is lost. Sandbox state is not
// restored after a loss. Overlapping executions return ErrSessionBusy.
type Slot struct {
    p      *Pool
    opts   CheckoutOptions
    mu     sync.Mutex
    s      *Session
    closed bool
}

func (k *Slot) Session() *Session                       // current session or nil
func (k *Slot) State() SessionState                     // SessionIdle without a session; SessionClosed after Close
func (k *Slot) Go(ctx context.Context, code string, opts *FeedOptions) (*Run, error)
func (k *Slot) FeedRun(ctx context.Context, code string, opts *FeedOptions) (any, error)
func (k *Slot) FeedStart(ctx context.Context, code string, opts *FeedOptions) (Snapshot, error)
func (k *Slot) Stop(ctx context.Context, policy ...StopPolicy) (Stopped, error)
func (k *Slot) Close(ctx context.Context, policy ...StopPolicy) error   // idempotent; later Go returns ErrSessionClosed

// ErrSlotClosed is not introduced; a closed Slot returns ErrSessionClosed.
```

`Slot.Go` returns an error (instead of a finished `*Run`) for checkout
failure, `ErrSessionBusy` and `ErrSessionClosed`, because the caller has no
`Run` to inspect before admission.

### 6.1 `lifecycle.go` — UPDATED

    delivered       bool

type stopRequest struct {

### 6.2 Phase mapping (unchanged phases, new meanings for the stop)

| phase | request (uncatchable) | request (catchable) | kill |
|---|---|---|---|
| Starting/Preparing | run ends with the reason before send (`StopAborted`) | same | n/a |
| Executing (Python runs, no suspension) | wait for the next suspension | wait | at `killAt` |
| Callback (host call running) | callback ctx cancelled; at return → `AbortFeed` | callback ctx cancelled; at return → resume with the exception, rotate callback ctx | at `killAt` |
| Paused (FeedStart snapshot) | `AbortFeed` now | resume with the exception now; the snapshot chain continues | at `killAt` |
| Control (Close/Dump in flight) | after the operation | after the operation | at `killAt` |
| Aborting | already in progress | — | at `killAt` |
| Finished | `StopFinished` | same | — |

## 7. Data flows

### 7.1 Policy resolution

1. `New`/`NewWebSocket`: `p.stop = opts.Stop.over(DefaultStopPolicy)`; `validate()` → `*OptionError`.
2. `Checkout`: `limits.stop = opts.Stop.over(p.stop)`; validate.
3. `Stop`/`Close`/`Shutdown`: `effective = policy[0].over(session.limits.stop)` (Shutdown: over `p.stop` per session, then over the session's own policy — i.e. `policy[0].over(s.limits.stop)`), validate.
4. Feed-context cancellation: `s.limits.stop` unchanged.
5. `Reason == nil` after resolution → `keyboardInterrupt`. `Timeout < 0` → kill at the request instant. `Catchable` and `Drain` do not inherit "true/non-zero → false/zero"; a call cannot switch `Catchable` off once the checkout set it (zero-value inheritance) — documented; use `KillNow` or an explicit `Timeout` instead.

### 7.2 `Run.Stop` — happy path, uncatchable, run at a host call

1. Validate policy; `req := requestStop(e, effective)`; if `Drain > 0`, arm `drainTimer`; `requestAt` stays zero until the timer fires or `Drain == 0`.
2. Request phase: `e.stop` set, `killAt = now + Timeout`, `e.cancelCallbacks()`, watchdog goroutine started (as `watchInterrupt` today).
3. The callback returns `ctx.Err()`; `endCallback` → `stopAtBoundary` → `errExecutionInterrupted` → `abortExecution` → `co.Abort(reason)` with deadline `killAt`.
4. Worker answers `Error` (KeyboardInterrupt); `finishExecution` resolves `req.kind = StopAborted`; `e.done` closed.
5. `Stop` returns `Stopped{How: StopAborted, Err: *RuntimeError{KeyboardInterrupt}, SessionErr: nil}`, `nil`.

### 7.3 `Run.Stop` — catchable

1–2 as above.
3. The callback returns; `endCallback` reports `deliver` instead of abort: the answerer resumes with `wire.ExtResult{Kind: ExtError, Error: reason}`; `e.delivered = true`; `e.callbackCtx, e.cancelCallbacks = context.WithCancel(...)` (rotated so later host calls get a live context); pending futures registered before delivery stay cancelled (their `AsyncContext` saw the old context).
4. Python catches, runs cleanup with host calls, returns → `Complete` → `StopFinished`, `Err: nil`. Python does not catch → `Error` event → `StopAborted`, `Err: *RuntimeError`.
5. Delivery at a `Paused` snapshot: the pending snapshot is resumed by the library with the error (its token becomes stale, `ErrSnapshotStale` on use); the chain continues through the next snapshot returned from a fresh `advance`. NOTE: because the application owns the snapshot chain, `Session.Stop` on a paused catchable execution delivers the exception and returns `StopFinished`/`StopAborted` only after the chain completes; before that it returns `StopPending` with `ctx.Err()`. Simpler and documented: a catchable stop of a paused snapshot MUST be driven by the application; `Session.Stop` returns after delivery with `How == StopPending`, `err == nil` is NOT allowed — therefore for `Paused` + `Catchable` the library falls back to `AbortFeed` (uncatchable). Recorded in §11.
6. Still not ended at `killAt` → 7.4 step 3.

### 7.4 `Run.Stop` — killed

1. Request delivered or not; Python never reaches a suspension, or the callback ignores its context.
2. Watchdog fires at `killAt`: `forceExecution` as today: `SessionKilledError{Reason}` becomes terminal, `co.Terminate`, `req.kind = StopKilled`.
3. `Stop` waits `e.done` up to `Join`; returns `Stopped{StopKilled, Err: *SessionKilledError, SessionErr: same}`, `nil`; or after `Join`: the same `Stopped` and `ErrCallbackDetached`.

### 7.5 `Run.Stop` — drain, finished, not running, before start

- `Drain > 0`: `Stop` waits `e.done` up to `Drain`; ended → `StopFinished` with the run's result. Timer expiry → request phase. A second `Stop` during the drain with a shorter effective `Drain`/`Timeout` shortens (`wake`).
- Run already finished before the call: `StopFinished`, `Err = e.err`, `SessionErr = s.Err()`.
- `Session.Stop` with no current execution: `StopNotRunning`, `Err nil`, `SessionErr = s.Err()`.
- Stop before the first send: `beginExecution`/`beginSend` see `e.stop` → run ends with the reason → `StopAborted` (`e.beforeStart` no longer needs its own kind).
- Caller ctx ends first: `Stopped{How: StopPending, SessionErr: s.Err()}`, `ctx.Err()`; the request keeps its deadlines; `Run.Wait`/`WaitContext` observe the end.
- Concurrent `Stop` calls: the first creates the request; later calls join it and can only shorten `requestAt`/`killAt`; all return the same `How`.

### 7.6 Feed-context cancellation (`Go`/`FeedRun`)

`installStepLocked` registers `context.AfterFunc(ctx, func(){ requestStop(e, s.limits.stop) })`.
Every phase then follows 7.2–7.4. `FeedRun` returns when the run ends (up to
`Drain+Timeout+Join` after ctx). `Go` callers observe it through `Wait`.
`FeedStart` chains: a cancelled step context requests a stop with the session
policy; the next resume delivers it (uncatchable `AbortFeed`, see 7.3 note).

### 7.7 `Session.Close(ctx, policy...)`

1. Terminal → nil. Existing close attempt → join it (as today).
2. `current != nil && phase != Paused` → `s.Stop(ctx, policy...)` first (the same request/kill/join path). On `StopPending` with `ctx.Err()` → return `ctx.Err()`; the stop continues and a background goroutine finishes the close after `e.done`.
3. `phase == Paused` → reclaim immediately (as today), token invalidated.
4. `co.Finish(ctx)`; terminal cause `ErrSessionClosed` (or the mapped error); `finishExecution` for a reclaimed paused execution.
5. `Close(ctx, KillNow)` = today's `CloseNow`: terminal at once, worker retired, callbacks signalled, no join; returns nil.

### 7.8 `Pool.Shutdown(ctx, policy...)`

1. `p.closed = true` under `sessionsMu` (admission ends).
2. Snapshot `p.sessions`; for each in parallel: `s.Close(ctx, effective)` where `effective = policy[0].over(s.limits.stop)`.
3. `p.inner.Close(ctx)` then `p.inner.waitDrained(ctx)`; `stopReapers`.
4. Returns the first non-nil session close error other than `ctx.Err()`, else `ctx.Err()` when the wait was cut short, else nil.
5. `internal/pool`: `Shutdown` loses `shutdownForceGrace` and `OnShutdown`; it becomes `Close` + `waitDrained(ctx)`. `Config.OnShutdown` removed.

### 7.9 `Pool.Run(ctx, code, opts)`

1. `opts == nil` → `&RunOptions{}`.
2. `s, err := p.Checkout(ctx, opts.CheckoutOptions)`; error → return.
3. `v, err := s.FeedRun(ctx, code, &opts.FeedOptions)`.
4. `cctx := context.WithTimeout(context.WithoutCancel(ctx), s.limits.stop.Timeout + s.limits.stop.Join)`; `_ = s.Close(cctx)` (no execution runs at this point; Close is a `Finish` turn or a no-op on a terminal session).
5. Return `v, err`.

### 7.10 `Slot`

- `acquire(ctx)`: `closed` → `ErrSessionClosed`; `s != nil && s.State() != SessionClosed` → reuse; else `p.Checkout(ctx, opts)` (a terminal old session needs no Close; `terminateSession` already retired it).
- `Go`: under `mu`: acquire; `s.State() != SessionIdle` → `ErrSessionBusy`; `run := s.Go(ctx, code, opts)`; return `run, nil`. (A race with a direct `Session()` user still surfaces through `run.Wait()` as `ErrSessionBusy`.)
- `FeedRun`/`FeedStart`: acquire, delegate.
- `Stop`: `s == nil` → `StopNotRunning`; else `s.Stop(ctx, policy...)`.
- `Close`: `closed = true`; `s != nil` → `s.Close(ctx, policy...)`; `s = nil`.
- `State`: `closed` → `SessionClosed`; `s == nil` → `SessionIdle`; else `s.State()`.

### 7.11 `Session.State()`

Under `life.mu`: `terminal != nil` → `SessionClosed`; `closeAttempt != nil || controlDone != nil` → `SessionRunning`; `current == nil` → `SessionIdle`; `current.phase == Paused` → `SessionPaused`; else `SessionRunning`.

### 7.12 Failure modes

| Situation | Behaviour | Result |
|---|---|---|
| Callback ignores its context | killed at `killAt`; join `Join` | `StopKilled` + `ErrCallbackDetached` when still running |
| Worker dies during the request phase | protocol owner classifies (`CrashedError`/`DisconnectError`) | `StopFinished`, `Err` = that error, `SessionErr` set |
| Server-side timeout closes the socket (N9) | as above | `StopFinished` with `DisconnectError{Code, Reason}` |
| `AbortFeed` turn exceeds `killAt` | `forceExecution` | `StopKilled` |
| `AbortFeed` returns a non-error reply | `ProtocolError`, session terminated (as today) | `StopFinished`, `Err` = `ProtocolError`, `SessionErr` set |
| Stop during `Close`/`Dump` control operation | request queued; applied after the operation | as the phase table |
| Two policies passed | `*OptionError{"at most one stop policy"}` | — |
| `Drain`/`Join` negative | `*OptionError` | — |
| `Pool.Run` checkout fails | error returned, nothing to close | — |
| `Slot.Go` on a closed slot | `ErrSessionClosed` | — |
| `DefaultStopPolicy` changed after `New` | no effect on existing pools | documented |
| Unknown method in `ParameterNames` | `*ValueError{"parameter names: unknown method X"}` at registration | — |

## 10. Pseudo-code

### 10.1 `StopPolicy.over` / `validate`

```go
func (p StopPolicy) over(base StopPolicy) StopPolicy {
    out := base
    if p.Drain != 0   { out.Drain = p.Drain }
    if p.Timeout != 0 { out.Timeout = p.Timeout }
    if p.Join != 0    { out.Join = p.Join }
    if p.Reason != nil { out.Reason = p.Reason }
    if p.Catchable    { out.Catchable = true }
    return out
}

func (p StopPolicy) validate() error {
    if p.Drain < 0 || p.Join < 0 { return &OptionError{Message: "stop policy: Drain and Join must be non-negative"} }
    return nil
}

func effectivePolicy(base StopPolicy, policy []StopPolicy) (StopPolicy, error) {
    if len(policy) > 1 { return StopPolicy{}, &OptionError{Message: "at most one stop policy"} }
    out := base
    if len(policy) == 1 { out = policy[0].over(base) }
    if out.Reason == nil { out.Reason = keyboardInterrupt }
    return out, out.validate()
}
```

### 10.2 `Run.Stop`

```go
func (r *Run) Stop(ctx context.Context, policy ...StopPolicy) (Stopped, error) {
    s, e := r.s, r.exec
    p, err := effectivePolicy(s.limits.stop, policy)
    if err != nil { return Stopped{}, err }
    if err := ctx.Err(); err != nil { return Stopped{How: StopPending, SessionErr: s.Err()}, err }

    req, immediate, done := s.requestStop(e, p)     // 10.3
    if done { return immediate, nil }                // finished / not current
    // wait for resolution (kind final) within ctx
    select {
    case <-req.resolved:
    case <-ctx.Done():
        if !channelClosed(req.resolved) { return Stopped{How: StopPending, SessionErr: s.Err()}, ctx.Err() }
    }
    st := s.stoppedFrom(e, req)                       // kind, e.err (after done) , terminal
    if st.How != StopKilled { <-e.done; st.Err = e.err; return st, nil }   // aborted/finished: the driver returns promptly
    // killed: join the Go callback up to Join
    timer := time.NewTimer(p.Join); defer timer.Stop()
    select {
    case <-e.done:            st.Err = e.err; return st, nil
    case <-ctx.Done():        return st, ctx.Err()
    case <-timer.C:           return st, ErrCallbackDetached
    }
}
```

Note: for `StopAborted`/`StopFinished` the wait on `e.done` is bounded by ctx as well (loop with `select`), omitted above for brevity.

### 10.3 `requestStop` (replaces `requestInterruptForStep`)

```go
func (s *Session) requestStop(e *execution, p StopPolicy) (req *stopRequest, immediate Stopped, done bool) {
    s.life.mu.Lock(); defer s.life.mu.Unlock()
    if e.phase == executionFinished || s.life.current != e {
        return nil, Stopped{How: StopFinished, Err: e.err, SessionErr: s.life.terminal}, true
    }
    if e.terminalCause != nil && e.stop == nil {           // lost while running, driver still returning
        return nil, Stopped{How: StopFinished, Err: e.terminalCause, SessionErr: s.life.terminal}, true
    }
    now := time.Now()
    if e.stop == nil {
        e.stop = &stopRequest{policy: p, wake: make(chan struct{}, 1), resolved: make(chan struct{})}
        e.stop.schedule(now)                               // requestAt = now+Drain; killAt = requestAt+Timeout (or requestAt when Timeout<0)
        go s.watchStop(e, e.stop)
    } else {
        e.stop.shorten(now, p)                             // only earlier requestAt/killAt; wake
    }
    if e.stop.requestAt.Equal(now) || e.stop.requestAt.Before(now) { s.enterRequestLocked(e) }
    return e.stop, Stopped{}, false
}

func (s *Session) enterRequestLocked(e *execution) {        // idempotent
    if e.stop.requested { return }
    e.stop.requested = true
    cancel := e.cancelCallbacks
    paused := e.phase == executionPaused
    if paused { e.phase = executionAborting; e.operationDone = make(chan struct{}) }
    go cancel()                                             // outside the lock in the real code
    if paused { go s.abortPaused(e) }                       // uncatchable for paused (see 7.3 note)
}
```

### 10.4 `watchStop` (replaces `watchInterrupt`)

```go
func (s *Session) watchStop(e *execution, req *stopRequest) {
    for {
        s.life.mu.Lock()
        if req.resolvedOnce { s.life.mu.Unlock(); return }
        next := req.killAt
        if !req.requested { next = req.requestAt }
        s.life.mu.Unlock()
        timer := time.NewTimer(time.Until(next))
        select {
        case <-req.resolved: timer.Stop(); return
        case <-req.wake:     timer.Stop()                       // deadlines changed
        case <-timer.C:
            s.life.mu.Lock()
            if !req.requested { s.enterRequestLocked(e); s.life.mu.Unlock(); continue }
            s.life.mu.Unlock()
            if s.forceExecution(e, req) { return }              // kills at killAt; StopKilled
        }
    }
}
```

`forceExecution` is today's code with `InterruptKilled` → `StopKilled` and
`SessionKilledError{Reason: req.policy.Reason}`.

### 10.5 Boundary handling with `Catchable`

```go
func (s *Session) stopAtBoundary(e *execution) error {
    // as today, then:
    if e.stop != nil && e.stop.requested {
        if e.stop.policy.Catchable && !e.delivered { return errDeliverStop }
        if e.stop.policy.Catchable && e.delivered  { return nil }          // cleanup continues until killAt
        return errExecutionInterrupted                                      // AbortFeed path
    }
    return nil
}

// answerer.callHost / resume paths:
//   errDeliverStop → mark e.delivered, rotate callback context, resumeError(reason type, message)
//   errExecutionInterrupted → abortExecution (unchanged)
func (s *Session) deliverStop(e *execution) (excType, msg string) {
    s.life.mu.Lock()
    e.delivered = true
    e.callbackCtx, e.cancelCallbacks = context.WithCancel(context.WithoutCancel(e.stepCtx))
    typ, m := exceptionParts(e.stop.policy.Reason)
    s.life.mu.Unlock()
    return typ, m
}
```

`finishExecution` resolves the kind: `beforeStart || aborted` → `StopAborted`;
otherwise `StopFinished` (a caught-and-completed run included). `terminalCause`
of a kill → `StopKilled` (set by `forceExecution`).

### 10.6 `Session.Close`

```go
func (s *Session) Close(ctx context.Context, policy ...StopPolicy) error {
    p, err := effectivePolicy(s.limits.stop, policy); if err != nil { return err }
    if p.Timeout < 0 { _ = s.terminateSession(ErrSessionClosed); return nil }        // KillNow == old CloseNow
    // join an existing attempt as today
    s.life.mu.Lock(); e := s.life.current; running := e != nil && e.phase != executionPaused; s.life.mu.Unlock()
    if running {
        st, err := (&Run{s: s, exec: e}).Stop(ctx, p)
        if err != nil && st.How == StopPending { go s.closeAfter(e, p); return err }   // continues in the background
        if st.SessionErr != nil { return nil }                                          // already terminal
    }
    return s.closeOwned(ctx)                                                            // as today: reclaim paused, Finish, terminate
}
```

### 10.7 `Pool.Shutdown`

```go
func (p *Pool) Shutdown(ctx context.Context, policy ...StopPolicy) error {
    p.sessionsMu.Lock(); p.closed.Store(true); open := keys(p.sessions); p.sessionsMu.Unlock()
    var wg sync.WaitGroup; errs := make([]error, len(open))
    for i, s := range open { wg.Add(1); go func() { defer wg.Done(); errs[i] = s.Close(ctx, policy...) }() }
    wg.Wait()
    _ = p.inner.Close(ctx)
    if err := p.inner.WaitDrained(ctx); err != nil { return err }
    p.inner.StopReapers()
    for _, err := range errs { if err != nil && !errors.Is(err, context.Canceled) && !errors.Is(err, context.DeadlineExceeded) { return err } }
    return ctx.Err()
}
```

### 10.8 `Pool.Run`, `Slot.Go`, `Session.State`

```go
func (p *Pool) Run(ctx context.Context, code string, opts *RunOptions) (any, error) {
    if opts == nil { opts = &RunOptions{} }
    s, err := p.Checkout(ctx, opts.CheckoutOptions); if err != nil { return nil, err }
    v, err := s.FeedRun(ctx, code, &opts.FeedOptions)
    cctx, cancel := context.WithTimeout(context.WithoutCancel(ctx), s.limits.stop.Timeout+s.limits.stop.Join); defer cancel()
    _ = s.Close(cctx)
    return v, err
}

func (k *Slot) Go(ctx context.Context, code string, opts *FeedOptions) (*Run, error) {
    k.mu.Lock(); defer k.mu.Unlock()
    s, err := k.acquireLocked(ctx); if err != nil { return nil, err }
    if st := s.State(); st != SessionIdle { if st == SessionClosed { return nil, s.Err() }; return nil, ErrSessionBusy }
    return s.Go(ctx, code, opts), nil
}

func (s *Session) State() SessionState {
    s.life.mu.Lock(); defer s.life.mu.Unlock()
    switch {
    case s.life.terminal != nil:                                   return SessionClosed
    case s.life.closeAttempt != nil || s.life.controlDone != nil:  return SessionRunning
    case s.life.current == nil:                                    return SessionIdle
    case s.life.current.phase == executionPaused:                  return SessionPaused
    default:                                                       return SessionRunning
    }
}
```
