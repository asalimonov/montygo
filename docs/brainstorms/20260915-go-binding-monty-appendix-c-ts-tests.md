# Appendix C — `@pydantic/monty` test inventory (HEAD) and portability classification

28 spec files, 489 runtime tests (471 native + 18 wasm), no `describe` blocks (flat `test()` grouped by `// ===== Section =====` banners). Harness: `setupPool()` = one pool per spec file (`beforeAll` create, `afterAll` close); `run(code, options)` splits flattened options into checkout-level (`scriptName, limits, typeCheck, typeCheckStubs, typeCheckFormat, typeCheckColor, assertMessageAnnotations, printFlushInterval`) and feed-level (`inputs, externalLookup, os, mount, cwd, printCallback, skipTypeCheck`), then checkout → feedRun → close. `assertMemoryError` parses `^MemoryError: memory limit exceeded: (\d+) bytes > (\d+) bytes$` with ±1024 B tolerance on used bytes. `os_paths.ts` provides `checkRelativePathResults` and `checkOsPathValidation` shared checks. `MONTY_BIN` is consumed by binary resolution, not by tests.

Legend: **[JS]** JS-runtime-specific; **[NODE]** needs host FS / child process / Node builtins; **[WASM]** 32-bit wasm target only.

## C.2 Portability summary

- **Fully portable (~380):** basic, inputs, async, external (minus JS prototype/Symbol/getter cases), exceptions (runtime/display/traceback halves), type_check, limits (minus transport unit), print, feed_start, pool lifecycle/crash/watchdog, mount, class_instance policy/identity/ClassType semantics, repl, install_dependencies, os_paths shared checks.
- **JS/Node-only (~110):** OTel SDK plumbing (17; span-name/parenting contracts are worth mirroring), packaging/docs (4 + N), TS codec/transport units (5), JS language mechanics (`await using`, `Buffer`, Map/Set identity, `__tuple__`, BigInt, Symbol, prototype denial, cross-realm Set, reference identity), platform-gated (Linux `/proc`, Unix `mkfifo`, win32 branches), wasm transport (18; 2 inherently 32-bit).
- **Byte-exact expectations to re-derive:** memory figures (89 113 / 75 047 / 10 031 312 / 1 281 313 / 4 031 972 / 1 060 648), 64 B per-entry overhead, ±1024 B tolerance.
